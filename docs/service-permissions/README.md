# Доступ службы KommitEye к существующим отчётам

Эта инструкция предназначена для службы `KommitEye`, работающей под
`NT SERVICE\KommitEye`, и стандартного каталога данных
`C:\ProgramData\KommitEye\Server\data`. Она помогает устранить ошибку вида:

```text
Access to the path 'C:\ProgramData\KommitEye\Server\data\server.lock' is denied.
```

Установщик и сервер не исправляют права автоматически. Следующие команды
выполняет администратор вручную. Они не удаляют и не переносят отчёты.

## 1. Проверить учётную запись и остановить службу

Открой **PowerShell от имени администратора**. Служба должна быть уже
зарегистрирована. Проверь её учётную запись и путь запуска:

```powershell
Get-CimInstance Win32_Service -Filter "Name='KommitEye'" |
    Select-Object Name, State, StartName, PathName
```

Продолжай, если `StartName` — `NT SERVICE\KommitEye`. Если указана другая
учётная запись, доступ нужен именно ей; не меняй её автоматически, поскольку
это может нарушить доступ к зашифрованным credentials.

```powershell
Stop-Service KommitEye -ErrorAction Stop
Get-Service KommitEye
```

Перед дальнейшими действиями статус должен быть `Stopped`. Также останови
запущенную вручную ZIP-версию, если она использует этот же каталог данных.

## 2. Выдать доступ к каталогу и существующим файлам

```powershell
icacls "C:\ProgramData\KommitEye\Server\data" /grant "NT SERVICE\KommitEye:(OI)(CI)M" /T
if ($LASTEXITCODE -ne 0) {
    throw "Не удалось выдать все права. Проверь сообщения icacls перед запуском службы."
}
```

- `M` — право изменения: чтение, создание, запись и удаление файлов, необходимые
  для работы приложения и SQLite. Это не полный контроль над правами папки.
- `(OI)(CI)` — наследование добавленного разрешения файлами и подпапками там,
  где наследование включено.
- `/T` — обработка существующих вложенных папок и файлов, включая `server.lock`
  и базы SQLite, даже если они не наследуют разрешения родителя.
- `/grant` без `:r` добавляет разрешения, сохраняя остальные правила доступа.
  Команда не включает и не отключает наследование и не меняет содержимое файлов.

В результате обработки не должно быть ошибок. Не используй `/reset` и не удаляй
базу или отчёты для устранения ошибки доступа. Если есть явные запрещающие правила
(`Deny`), добавленного разрешения может быть недостаточно: их должен отдельно
проверить администратор.

## 3. Проверить путь к старым данным

Открой конфигурацию, указанную в `PathName` службы после `--config`.
По умолчанию это:

```text
C:\ProgramData\KommitEye\Server\server.json
```

Убедись, что поле `DataDirectory` указывает на каталог с твоими данными:

```json
"DataDirectory": "C:\\ProgramData\\KommitEye\\Server\\data"
```

Это одна строка существующего JSON, а не замена всего файла. Сохрани остальные
настройки, включая `CredentialProtection`. Выдача файловых прав не переносит
credentials между учётными записями и не меняет способ их шифрования.

Если используется другой каталог, укажи его также в команде выдачи прав выше.
Сервер должен открыть именно каталог, где находятся твои отчёты.

## 4. Запустить и проверить

```powershell
Start-Service KommitEye -ErrorAction Stop
Get-Service KommitEye
```

Ожидаемый статус — **Running**. Открой веб-интерфейс на настроенном адресе
(по умолчанию `http://localhost:5080`) и проверь раздел Reports.

Если запуск снова не удался, открой **Просмотр событий → Журналы Windows →
Приложение** и найди сообщение KommitEye или `.NET Runtime` с точным путём ошибки.
Права на каталог данных не дают доступ к другим папкам: службе также нужны
чтение/выполнение программы и Git, чтение конфигурации и необходимый доступ к
репозиториям. Не выдавай права на весь `C:\ProgramData` или весь диск.

Дополнительно: [команды службы и требования к доступу](../windows-installer.md#executable-service-commands),
[документация Microsoft по icacls](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls).
